{{ octicon("pulse", 20) }} System Architecture

Patchwork is an autonomous CI remediation service designed for GitHub Actions. It monitors failed builds, analyzes logs and source code, executes repairs in an isolated sandbox, and submits pull requests once tests pass.

Figure 1. Deterministic event flow: from Actions failure to verified Pull Request

{{ octicon("checklist", 20) }} Prerequisites

Before beginning, ensure you have:

  • A GitHub account with admin access to the repository you want to remediate.
  • A repository that uses GitHub Actions (e.g. running pytest, npm test, etc.).
  • An AI API Key: Google Gemini (recommended: gemini-2.5-flash) or OpenAI.
  • A free Smee.io channel URL for receiving webhooks locally without exposing public ports.

1 Create a GitHub App

Patchwork uses a GitHub App to securely authenticate, fetch workflow run logs, and open pull requests under your bot's identity.

{{ octicon("repo", 16) }} GitHub App Registration Steps
  1. In GitHub, navigate to Settings → Developer Settings → GitHub Apps → Click New GitHub App.
  2. GitHub App name: Choose a name, e.g. Patchwork-AutoFix-YourOrg.
  3. Homepage URL: Enter your local dashboard or repo URL, e.g. http://127.0.0.1:8000.
  4. Webhook: Keep Active checked.
  5. Webhook URL: Paste your Smee channel URL (see Step 4 below), e.g. https://smee.io/your-unique-id.
  6. Webhook secret: Enter a secret passphrase (e.g. 32 random characters). Save this secret to enter into Patchwork Settings.

2 Configure Repository Permissions & Events

On the same GitHub App creation page, expand the Permissions and Subscribe to events sections.

Permission Category Access Level Why Patchwork Needs It
Actions Read-only To download workflow run failure logs and extract stack traces.
Contents Read and write To inspect source code, create ai-fix/* branches, and commit patches.
Pull requests Read and write To open automated Pull Requests containing the verified fix and diagnosis.
Workflows Read and write To inspect workflow trigger definitions and requirements.
{{ octicon("alert-fill", 18) }}
CRITICAL: Subscribe to "Workflow run" Events
Under Subscribe to events, you MUST check the box for Workflow run. If this box is left unchecked, GitHub will NEVER send webhook notifications when your GitHub Actions fail, and Patchwork will not be triggered.
Figure 2. Check the "Workflow run" event under Subscribe to events in your GitHub App

3 Private Key & App Installation

After clicking Create GitHub App:

  1. Note the App ID: Located in the "About" section near the top (e.g. 5801640).
  2. Generate Private Key: Scroll down to Private keys and click Generate a private key. A .pem file will download to your computer.
  3. Install on Repositories: In the left navigation menu of your GitHub App, click Install App. Click Install next to your personal account or organization, and choose Only select repositories (select your target repo, e.g. Fizzy444/Test).
{{ octicon("check-circle-fill", 18) }}
Saving in Patchwork Settings
Navigate to Patchwork Settings → GitHub App. Paste your App ID, and in Private key, paste the full text of your .pem file (including -----BEGIN RSA PRIVATE KEY----- and -----END RSA PRIVATE KEY-----).

4 Webhook & Automatic Smee Setup

During local development or internal deployments, GitHub cannot directly reach localhost:8000. Smee.io provides a free, encrypted webhook proxy created by GitHub.

{{ octicon("plug", 16) }} 1-Click Smee Integration (No Terminal Needed)
  1. Go to https://smee.io and click Start a new channel.
  2. Copy your unique channel URL (e.g. https://smee.io/BviW0t0idFkksxc).
  3. In your GitHub App settings, set Webhook URL to this Smee URL.
  4. In Patchwork Settings → Webhook, paste the same Smee URL into Webhook payload URL (or Smee URL).
  5. Click Save Webhook.
{{ octicon("sync", 18) }}
Automatic Background Runner
As soon as you save a smee.io URL, Patchwork automatically launches its native async SSE client in the background. You do NOT need to install smee-client or leave a terminal window running.

5 Configure AI Provider

Patchwork supports Google Gemini, Anthropic Claude, and OpenAI. Gemini 2.5 Flash and Claude 3.5 Sonnet are recommended for fast, deterministic code diagnosis.

  1. Open Settings → AI provider.
  2. Provider: Select Google Gemini, Anthropic Claude, or OpenAI.
  3. Model: Enter your preferred model, e.g. gemini-2.5-flash, claude-3-5-sonnet-20241022, or gpt-4o.
  4. API Key: Paste the API key for your chosen provider (from Google AI Studio, Anthropic Console, or OpenAI Platform).
  5. Click Save AI provider.

6 Trigger a Failure & Verify Remediation

You are now completely set up! Let's test the autonomous loop:

{{ octicon("commit", 16) }} Test Walkthrough
  1. In your connected repository, introduce a failing assertion in your code: 
    def square(x):
-   return x ** 2
+   return x + 2  # Intentional bug
  2. Commit and push to trigger your GitHub Actions workflow.
  3. Once GitHub Actions finishes with failure, watch your Patchwork Overview and Jobs page.
  4. Patchwork extracts the failure trace, diagnoses square(2), tests the patch in the sandbox, and opens a Pull Request on GitHub!

{{ octicon("book", 20) }} Frequently Asked Questions

Do I need both a GitHub App and a Personal Access Token?

No. A GitHub App is the recommended and standard setup. The "Development token" field in Settings is strictly an optional fallback for local testing without an App.

Does Smee have to be running in my terminal?

No! Patchwork includes a built-in async Smee runner. As long as your Smee link is entered in Patchwork Settings, the app connects to Smee over Server-Sent Events and forwards incoming webhooks automatically.

How does Patchwork prevent modifying tests?

Patchwork enforces a strict guardrail: paths matching tests/**, test_*.py, *.spec.ts, or .github/** are protected. If an AI patch proposes modifying any protected file, the patch is rejected immediately with a NEVER_TOUCH_TESTS guardrail violation.

{{ octicon("alert-fill", 20) }} Troubleshooting

{{ octicon("x-circle-fill", 16) }} "My GitHub Action failed, but nothing happened in Patchwork"

Check the following 3 checkpoints:

  1. Is "Workflow run" subscribed? In your GitHub App settings → Permissions & events → Subscribe to events, ensure Workflow run is checked.
  2. Is the App installed on the repo? In GitHub App settings → Install App, ensure the app is installed on the specific repository where the action ran.
  3. Is the Smee runner active? Open Patchwork Settings. The "Smee Auto-Runner" sidebar card should say Active.
